## 1. 一句话结论

**根因链已全部实锤，但存在 three.js MMDPhysics 引擎级结构性限制（硬 Bullet 限位 vs MMM 软弹簧限位），bake 工具层无法完全复现 MMM 的裙摆自然下垂；中下裙摆已修好（1-6°→15-29° 接近 MMM），顶圈侧摆骨过摆是引擎限制。**

## 2. 核心根因（两个，都已实锤）

### 2.1 旋转轴错位根因（已修复 ✅）— 手写循环缺游戏侧驱动链

**现象**：bake 主轴 X≈60/Y≈47（均匀），游戏 X=104/Y=20、MMM X=107/Y=11 —— bake 旋转轴从 X（正确前后摆）错位到 Y（垂直转）。

**根因**：bake-physics.mjs 手写模拟循环缺游戏侧 `_animatePMXMesh` 驱动链：
- PMX 动画路径（updateOne 逐骨 transformationClass 排序处理 grant+IK）
- `_restoreBones` / `_saveBones`（骨骼矩阵保存恢复）
- `_optimizeIK`（依赖 rigidBodyType，之前 bake 恒 -1 已按 MMDLoader boneTypeTable 修正）

**修复**：`config.helperDriver=true`（bake 改用 MMDAnimationHelper 完整驱动）→ 主轴 X=73/Y=28（X 主导）✅。对比表：游戏 X=104/Y=20 | MMM X=107/Y=11 | bake 手写 X≈60/Y≈47 | bake helper X=73/Y=28。

### 2.2 裙摆起身阶段不自然下垂根因（已定位，引擎级未解 🔴）— 硬限位 vs 软弹簧

**现象**（兄弟 MMD 实测）：抓起起身阶段裙摆被拉起，不自然下垂。数据：bake 裙摆下部骨旋转仅 1-6°（MMM 15-32°）。

**根因**：PMX 裙子垂直约束 Y 轴 `rotationLimitation = [0°, 0°]`（完全锁死），X 轴 [-50°, +1°]：
- **three.js MMDPhysics（Ammo.js btGeneric6DofSpringConstraint）**：limit=0 → **硬 Bullet 锁定**（setAngularLowerLimit/UpperLimit 相同 → 完全不可旋转）→ 裙摆跟随身体
- **MMM/BulletSharp**：同样参数解释为**软弹簧目标范围** → 允许超出限位被弹簧拉回 → 自然下垂
- X 轴上界 +1° 阻止裙摆向前摆（落在身体前面）
- spring equilibrium 只在构造时设一次（frame-0 位姿），不像 MMD 每帧跟踪身体运动更新平衡点

**bake 工具层修复**（已做，部分有效）：`rotationLimitScale` 逐轴数组 + `unlockAngularRange` + `rotationLimitOverride`（bake-physics.mjs L412-449），仅对含 springRotation 的约束生效（跳过水平环约束）。

|---|---|---|---|---|
| スカート_14_3 底部前 | 1.1° | **16.1°** | 14.7° | ✅ 接近 |
| スカート_14_10 底部侧 | 4.3° | **29.3°** | 24.2° | ✅ 接近 |

**结构性限制**：顶圈侧摆骨 Y 轴解锁实验 5 轮（Run1-Run5），解锁 Y 轴总是导致 0_10 更严重过摆（≥133°）——three.js 硬限制无法复现 MMM 软弹簧行为，**引擎级差异**。

## 3. 完整实验历程

### 3.1 阶段一：参数扫描（fix1-fix5，手写循环时代 8/6-8/7）
- 15+ config 参数：坐标转换、position、frame0、setEquilibriumPoint、刚体初始 transform、初始姿态、调用顺序、世界矩阵刷新、锁定轴 ERP/CFM、spring 刚度、solver 迭代、temporalKinematic、Ammo 构建差异（ammoSource='game' 切换）——**全部无效**（主轴仍均匀分布）
- fix4 实锤：solverIterations=50 + springStiffnessScale=2000（起身段最优）
- fix5 胸部维度：÷1000 最优（左胸上 f75 267→30.7°）
- 教训：analyze-bake-vs-mmm.cjs 的 relAng 用 Math.abs() 只比角度大小，**旋转轴不同也显示接近**——脚本骗人，必须用 verify-rotation-axis.cjs 看主轴分布

### 3.2 阶段二：helper 驱动（8/7 根因修复 ✅）
- 方向 1（兄弟拍板）：bake 改用 MMDAnimationHelper 完整驱动
- helper.add(mesh, {animation, physics:true}) → 内部 _setupMeshPhysics 官方 warmup
- helper.configuration.pmxAnimation=true（HMS 是 PMX）→ _animatePMXMesh/updateOne
- 主轴 X=73/Y=28 ✅ 根因=手写循环缺游戏侧步骤
- 产物：pickup_bake_helper.vmd（全物理骨 avg 20.32°，裙撑骨 1.3-2.7°）

### 3.3 阶段三：裙子调优（8/8 Flash 轮）
- 整体参数扫描 8 组（stiffness 250-4000 × damping 0.05/0.3）→ **全部无效**（23.6-28.2°）
- **突破：碰撞 mask**——zoneRules 去腿碰撞 `noCollisionGroups:[1]`（对齐 MMM mask 分离摆动）→ 21.14°
- 最优 E4v2：去腿碰撞 + 欠摆骨更软(scale3000) + 过摆骨更硬(scale300) → **20.90°**
- 产物：pickup_bake_helper_skirt.vmd + bake-config-helper-skirt.json（zoneRules 三区）

### 3.4 阶段四：起身阶段根因（8/8 Pro 轮）
- 数据实锤：bake 裙摆下部骨 1-6° vs MMM 15-32°（锁死跟随身体）；顶圈侧 0_10 过摆 96.4°（f45+ 主轴 X-→Y- 漂移）
- 根因：硬限位 vs 软弹簧（见 2.2）
- Run 2 最优：Z1+Z3 解锁限位、Z2（顶圈侧）无限位 → 中下裙摆 15-29° ✅
- 产物：pickup_bake_helper_skirt2.vmd + skirt-root-cause-report.md

## 6. 纪律教训

- 🔴 分析脚本必须看**主轴分布**（verify-rotation-axis.cjs），不能只看角度大小（Math.abs 骗人）
- 🔴 bake 与游戏的关键差异 = 驱动链（helper vs 手写循环），先对齐驱动链再谈参数
- 🔴 碰撞 mask（去腿碰撞）是裙子调优最大杠杆，弹簧刚度整体扫描无效
- 🔴 three.js 硬限位 vs MMM 软弹簧 = 引擎级差异，工具层调参无法完全绕过，需兄弟决策方向
- 🔴 兄弟 MMD 实测是最终验收（脚本误差只能参考，如 avg 20.90° 但实测「被拉起」）
